# AI-PPT-Skill 视觉探索实验｜阶段性实验记录

**日期：** 2026-09-30  
**项目：** AI-PPT-Skill  
**当前阶段：** 原型验证 / 视觉探索机制验证  
**实验对象：** 《数智兴农实践队》暑期社会实践答辩封面  
**本文件用途：** 记录当前 A′ / B / C 实验设计、豆包与 GPT 两轮结果、已知证据、限制、阶段性结论与下一步建议。  

---

## 1. 实验背景

当前问题不是“如何把某一张封面修得更漂亮”，而是判断 AI-PPT-Skill 在视觉探索阶段到底发生了什么：

1. 当前 Skill 是否因为前置方法论与视觉约束过重，压缩了视觉探索空间；
2. 在最小约束下，模型能否产生更有差异、更有潜力的视觉方向；
3. 高质量参考图是否能够提高视觉上限；
4. 不同模型 / 生图链路之间，结果是否存在稳定规律；
5. Professional Mode 应如何区分“探索”和“收敛”。

当前方法论总原则：

> **探索阶段高自由度，收敛阶段高纪律。**

该历史结果仅用于说明旧流程问题，不进入正式 A′ / B / C 比较。

### 2.2 A′ — Current Skill Re-run

目的：

为避免实验协议污染，使用单独基线分支：

`experiment-a-baseline-20260929`

该分支固定在加入实验协议之前的仓库状态。

已确认当前 Skill 在 Step 5 中引用以下文件：

但这些文件在基线分支中实际不存在，均为 404。  
正式 A′ 运行中必须记录该事实，不补写、不重建。

### 2.3 B — Minimal-Constraint Free Exploration

只保留：

- 项目身份；
- 核心叙事；
- 真实经历；
- 期望感受；
- 三条真实性硬边界；
- 3 张真正不同候选的输出要求。

明确要求：

- 不先定义风格；
- 不解释设计理念；
- 不自检；
- 不加载 Skill；
- 不提供参考图；
- 直接视觉探索。

目的：

> 测试在最小约束下，模型能否打开更宽的视觉搜索空间。

### 2.4 C — Minimal Free Exploration + Strong Reference

与 B 主体 Prompt 保持一致。

唯一新增变量：

- 1 张用户认可的强视觉参考图；
- 仅允许学习整体风格、视觉张力、层级、空间关系、图文关系与完成度；
- 禁止复制具体文字、地点、地图、照片、事实内容和版式细节。

目的：

> 测试参考图是否显著提高生成质量，或是否导致机械模仿 / 方向坍缩。

## 3. 控制变量原则

同一模型的一轮正式实验，应尽量保持：

- 同一个模型 / 产品入口；
- 同一 thinking / 推理设置；
- 三个全新独立对话；
- 相同项目事实；
- 相同输出数量：3 张；
- 相同 16:9；
- 相同封面文字；
- 第一轮生成后不修改；
- 不向生成模型透露其他组结果；
- 不向模型透露用户上一轮偏好。

因此正式比较对象是：

| 模型 | A′ 当前 Skill | B 自由探索 | C 自由探索 + 参考图 |
|---|---|---|---|
| 豆包 | 已完成 | 已完成 | 已完成 |
| GPT | 已完成 | 已完成 | 已完成 |

## 4. 豆包实验结果

### 4.1 豆包 A′

A′ 运行时的关键过程：

- 正确读取基线分支；
- 明确确认 5 个 `references/*` 文件全部 404；
- 未自行补写缺失文件；
- 按当前 Professional Mode 先形成 Visual Intent；
- 生成前主动收敛为 3 个方向：
  1. 暖色纸本「田野档案」
  2. 浅色留白「现场路线」
  3. 深色层次「收敛」氛围风

正式结果：

- A′1：深色抽象科技氛围、粒子、发光收敛点；
- A′2：浅色路线 / 节点信息图；
- A′3：米白地形线稿 + 定位点。

### 4.2 豆包 B

三张候选：

- B1：桌面静物 / 安全帽 / 笔记本 / 工牌 / 杯子；
- B2：浅蓝地形线稿 + 路径 / 定位；
- B3：档案册 / 记录本 / 图片 / 折线图拼贴。

该组在视觉逻辑上差异较大。

### 4.3 豆包 C

三张候选：

- C1：01 / 02 / 03 三块卡片式档案拼贴；
- C2：深蓝背景、远处红色信标 / 温室、抽象“预测—现场—判断”；
- C3：米白底、大横向养殖场版画 + 红色路线节点。

### 4.4 豆包 9 张盲评

将 A′ / B / C 共 9 张打乱为 P1–P9 后，用户进行第一轮盲评。

| 匿名编号 | 原始编号 | 用户反馈 |
|---|---|---|
| P1 | A′1 | 最差 |
| P2 | B1 | 最差 |
| P3 | C1 | 勉强较好 |
| P4 | C2 | 中规中矩 |
| P5 | B3 | 勉强较好 |
| P6 | C3 | 中规中矩 |
| P7 | A′2 | 最差 |
| P8 | B2 | 勉强较好 |
| P9 | A′3 | 勉强较好 |

用户原始结论：

> P8、P9、P5、P3 比其他的好，但也仅限勉强好点；P1、P2、P7 最差；其他中规中矩。

### 豆包盲评可支持的事实

1. 没有任何一张形成“强信号”；
2. A′ 三张中有两张进入“最差”；
3. B 三张中两张进入“勉强较好”，一张进入“最差”；
4. C 三张没有进入“最差”，但也没有产生明显强信号；
5. C 在这一轮更像是抬高了下限，而没有证明抬高了上限。

### 豆包结果暂不能支持的强结论

由于每组仅 3 张，不应直接下结论：

- “B 一定优于 A′”；
- “C 一定优于 B”；
- “参考图一定提升视觉上限”。

当前只能视为第一轮信号。

## 6. GPT 实验结果

**重要：GPT 三组目前尚未进行与豆包同样的正式盲评。**

因此以下判断主要是：

- 组内结构观察；
- 风格差异观察；
- 探索宽度观察；

不能把这些直接等价为“用户喜欢 / 不喜欢”。

### 6.1 GPT-B：无参考图自由探索

三张方向差异明显。

#### GPT-B1
空间路径型：

- 山地远景；
- 连续道路；
- 多个实践节点；
- 从现场走向产业的路线感。

#### GPT-B2
流程解释型：

- 左侧“预测”数据；
- 中间现场卡片；
- 右侧“判断 / 建议”；
- 更接近科技说明图 / dashboard 边缘。

#### GPT-B3
证据档案型：

- 地图；
- 调研手记；
- 纸张；
- 材料；
- 调研路径；
- 档案拼贴。

### GPT-B 组内观察

- 视觉逻辑差异较大；
- 探索宽度高；
- 方向更散；
- 质量与风格稳定性较低；
- 容易出现明显跑偏方向。

阶段性角色：

> **更像“探索器”。**

### 6.2 GPT-C：有参考图

三张高度同质。

共同特征：

- 米白纸张；
- 深蓝 / 赭红；
- 超大中文标题；
- “兴农”特殊强调；
- 山地 / 城市 / 产业拼贴；
- 红色路线 / 笔刷；
- 右侧几何切片；
- 高完成度编辑设计。

### GPT-C 组内观察

- 三张整体完成度较高；
- 视觉一致性高；
- 参考图控制力非常强；
- 但三张不是三个真正不同方向；
- 更像同一母版的三次变体；
- 探索宽度明显下降。

阶段性现象：

> **参考图提高了控制力，但造成明显“参考图重力 / direction collapse”。**

可描述为：

- high consistency；
- low exploration breadth；
- possible mode collapse。

阶段性角色：

> **更像“收敛器”。**

### 6.3 GPT-A′：当前 Skill

#### GPT-A′1
空间路径 / 地形路线型：

- 白底红黑；
- 山地地形；
- 红色路线串联节点；
- 武汉养殖场 → 荣昌 → 国农集团 → 中华保险。

#### GPT-A′2
流程 / 判断型：

- 节点路径；
- 信息卡片；
- 图表；
- 结果导向；
- 与 A′1 属于相近母题。

#### GPT-A′3
证据 / 档案型：

- 档案袋；
- 地图；
- 照片占位；
- 标签页；
- 实践材料。

### GPT-A′ 组内观察

三张不是完全独立的三种方向，更接近：

> **2 + 1**

其中：

- A′1 / A′2 属于“路径—节点—判断”母题；
- A′3 属于“档案—材料—证据”母题。

当前 Skill 的作用更像：

- 提供叙事骨架；
- 把模型推向几个“可解释”的视觉母题；
- 让结果比 B 更结构化；
- 但没有像 C 那样完全风格坍缩。

阶段性角色：

> **更像“结构化约束器”。**

## 7. 豆包与 GPT 的交叉观察

### 7.1 B：自由探索

豆包与 GPT 都表现出：

- 组内差异较大；
- 更容易出现完全不同的视觉逻辑；
- 同时质量波动更大；
- 跑偏风险更高。

这支持一个初步判断：

> 最小约束更有利于打开搜索空间，但不能保证下限。

### 7.2 C：强参考图

GPT 中表现非常明显：

- 完成度与风格一致性显著提高；
- 但 3 个方向严重同质化。

豆包 C 没有 GPT-C 那么极端，但同样没有明显出现超出 B 的“惊喜上限”。

这支持一个重要假设：

> 参考图更像一种**控制力 / 收敛工具**，而不一定是“探索放大器”。

### 7.3 A′：当前 Skill

豆包 A′：

- 先命名 Visual Intent；
- 再主动预设若干视觉方向；
- 两张最终进入用户“最差”。

GPT A′：

- 明显比 B 更结构化；
- 但三张仍主要围绕少数可解释母题；
- 探索宽度介于 B 与 C 之间。

初步推测：

> 当前 Skill 不是“完全无效”，而是可能**过早把探索转译成可讲述的视觉母题**。

正向作用：
- 减少完全随机输出；
- 更容易贴合叙事；
- 更容易形成“答辩逻辑”。

负向作用：
- 还没有充分探索，就提前开始收敛；
- 三个候选容易变成少数母题的变体；
- “Visual Intent → 方向命名 → 出图”可能形成早期锁定。

## 8. 当前最重要的阶段性结论

### 8.1 较强证据支持

#### 结论 A：参考图会显著改变探索行为

尤其在 GPT 中：

> 强参考图可以明显提高风格控制力与一致性，但会显著降低探索宽度。

因此：

> 参考图不应默认被理解为“提高探索上限”的工具。

它更可能适合收敛阶段。

#### 结论 B：自由探索确实能打开更多视觉分支

B 组在豆包与 GPT 中都表现出更明显的组内差异。

因此：

> 最小约束有利于扩大搜索空间。

但同时：

> 自由度越高，输出质量下限与主题稳定性越难保证。

#### 结论 C：当前 Skill 会主动结构化视觉探索

A′ 的输出并非完全随机。

它通常会：

1. 提炼 Visual Intent；
2. 命名视觉母题；
3. 再生成对应视觉。

这证明当前 Skill 有实际作用。

但其副作用可能是：

> 过早命名、过早解释、过早收敛。

### 8.2 仍不能正式下结论

当前还不能证明：

1. “B 一定优于 A′”；
2. “C 一定比 B 完成度更高”；
3. “空间痕迹 / 证据痕迹”已经是用户最终审美偏好；
4. Taste Discovery 应立即写入核心 Skill；
5. 当前 Skill 一定需要删除 Visual Intent；
6. 某一模型优于另一模型。

原因：

- 豆包只有 1 次正式盲评；
- GPT 还没有正式盲评；
- 每组仅 3 张；
- 不同平台生图链路不同；
- 个别候选可能受平台默认视觉先验影响；
- 目前没有 replicate 2。

## 9. 新增评价维度：Exploration Breadth

当前实验暴露出一个此前没有充分独立评价的指标：

> **Exploration Breadth / 探索宽度**

它不同于：

- 单张完成度；
- 风格一致性；
- 项目契合；
- 可扩展性。

例如 GPT-C：

- 单张完成度：较高；
- 风格一致性：很高；
- 参考图遵循：很高；
- 探索宽度：很低。

而 GPT-B：

- 单张稳定性：较低；
- 跑偏风险：较高；
- 探索宽度：明显更高。

因此 Professional Mode 的视觉探索阶段应明确关注：

> 是否真的覆盖多个“设计空间”，而不是生成 3 张同风格变体。

## 10. 当前用户偏好假设

基于豆包盲评，目前存在一个值得继续测试的假设：

> 用户更可能偏好“真实实践留下的痕迹被组织成设计”，而不是额外套一个风格模板。

### α. 空间痕迹

可能包含：

- 路线；
- 地图；
- 地形；
- 定位；
- 节点；
- 城市 / 现场之间的移动；
- 行进过程；
- 空间证据。

### β. 证据痕迹

可能包含：

- 真实照片；
- 调研记录；
- 材料；
- 数据截图；
- 文件；
- 地图碎片；
- 日期；
- 编号；
- 手写批注；
- 行程记录；
- 实践证据。

注意：

> 这里的关键不是“做成手账风 / 地图风”，而是让设计从真实材料与真实实践痕迹中长出来。

---

## 11. 当前明确不值得继续发展的方向

至少在当前测试项目中，应降低优先级：

### 1. 抽象科技氛围
- 发光点；
- 粒子；
- 科技蓝；
- 未来感；
- 大量抽象收敛隐喻。

### 2. 标准 dashboard / 商业流程图
- 常规节点图；
- 企业咨询风；
- 三段式流程图；
- 信息图堆叠。

### 3. 虚构氛围摄影
- 人工摆拍式道具；
- 看起来像“实践现场”的假照片；
- 与真实项目证据无关的氛围图。

### 4. 参考图直接统治整个探索阶段
- 容易造成 direction collapse；
- 三张候选变成同一风格变体；
- 探索价值显著下降。

## 12. 对 Professional Mode 的当前修正假设

**暂不写入核心 Skill，仅作为实验假设。**

更合理的视觉阶段可能是：

```text
Visual Exploration
↓
User Reaction
↓
Taste Discovery
↓
Direction Confirmation
↓
Reference-assisted Refinement
↓
Visual Lock
↓
Production
```

而不是：

```text
Visual Intent
↓
Reference
↓
Representative Render
↓
Visual Lock
```

### 12.1 探索阶段

目标：

> 找到“值得继续挖”的方向，不追求立即成熟。

建议：

- 不给强参考图；
- 只保留真实性与场景硬边界；
- 不先锁视觉母题；
- 不要求模型长篇解释；
- 不让模型自己判定审美 PASS；
- 要求候选在视觉逻辑上真正分叉。

### 12.2 Taste Discovery

只有当用户出现：

> “这张还不够好，但这里有点感觉”

才进入。

任务：

- 识别用户真正响应的是：
  - 空间关系；
  - 材料痕迹；
  - 图片比例；
  - 非对称；
  - 真实证据；
  - 行动感；
  - 留白；
  - 信息密度；
  - 页面不像传统 PPT；
  - 其他底层特征。

此时不急着改字体、颜色、字号。

### 12.3 参考图阶段

当前实验更支持将参考图放到：

> **方向已初步确定之后。**

参考图的主要作用可能是：

- 抬高完成度；
- 控制风格；
- 帮助空间比例；
- 控制图文关系；
- 稳定跨页系统。

而不是：

> 负责第一次自由探索。

### 12.4 Visual Lock

继续后移。

Visual Lock 的作用：

> 保护已被用户确认的好方向。

而不是：

> 在好方向出现之前限制搜索空间。

## 15. 下一步实验建议

下一轮不再继续扩大 A′ / B / C。

更值得做的是：

### Direction α — 空间痕迹

目标：

> 验证“空间路径 / 地图 / 地形 / 节点”是否真的接近用户审美，而不是豆包盲评中的偶然结果。

要求：

- 2 张同源但结构明显不同；
- 不照抄已有候选；
- 不用强参考图；
- 不提前锁配色；
- 不把路线图做成标准信息图；
- 尽可能让“实践的空间关系”成为视觉主体。

### Direction β — 证据痕迹

目标：

> 验证“真实材料 / 调研证据 / 记录系统”是否真正是用户偏好。

要求：

- 2 张同源但结构明显不同；
- 使用“真实证据感”，但禁止伪造真实照片与材料；
- 若没有真实材料，应明确使用占位；
- 不做泛化手账 / scrapbook 模板；
- 重点测试“真实证据如何变成设计”。

### 第二轮评价目标

不再问：

> 哪张最漂亮？

而是问：

1. 哪条方向更像“我”？
2. 哪条方向更像这个项目？
3. 哪个方向更值得继续做 20 页？
4. 哪些具体特征真正让用户产生正反馈？
5. 用户喜欢的是方向本身，还是某个偶然视觉细节？
